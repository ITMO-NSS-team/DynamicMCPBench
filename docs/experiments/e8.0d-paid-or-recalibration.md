# E8.0d — Paid-OR recalibration (post free-endpoint death)

## Question / hypothesis

The private free endpoint died 2026-06-10. The 5 surviving model lineages
now route through OpenRouter at paid prices. Direct question: **what does
the same calibration condition cost on OR, and do the models still
behave like they did on the free endpoint?**

Same N=10 sample on `specs/v3.jsonl` as E8.0a and E8.0b so this report is
a direct three-way comparison.

## Method

- Same condition as E8.0a/E8.0b: `dmcp eval --replay --pool target
  --p-alt 0.5 --pool-size 8 --budget 12 --repeat 1`.
- 5 OR-prefixed models (kimi-k2.5 retired): `deepseek/deepseek-v4-pro`,
  `moonshotai/kimi-k2.6`, `z-ai/glm-5.1`, `openai/gpt-oss-120b`,
  `minimax/minimax-m3`.
- `--concurrency 5` requested, capped to 1 (single `OPENROUTER_API_KEY`
  configured in `.env`); 5 cells ran sequentially.
- Direct cost: **\$0.36** total (sum of `mean_cost_usd × runs` across
  the panel). Wall time: ~30 min.

## Pre-registered decision rule

Calibration-only experiment — no strict pass/fail. Records the per-spec
\$ to use as the planning input for E8.9 / E8.7-v2 budget conversations.

## Reproduce

```
uv run python scripts/cost_calibration.py \
  --paid-or-pool \
  --n 10 \
  --specs specs/v3.jsonl \
  --reference-traces traces/v3.jsonl \
  --manifest manifests/servers.json \
  --concurrency 5 \
  --out reports/cost_calibration_or \
  --json docs/experiments/e8.0d_numbers.json
```

### Findings

1. **All 5 models actually work on paid OR.** Both E8.8's 0% twins
   (`gpt-oss-120b`, `minimax-m2p7` → `minimax-m3`) come back to life:
   50% and 90% respectively. The 0% result on E8.8 was a free-endpoint
   issue (the bare-name routing returned malformed responses at the
   leaderboard's traffic volume), **not** a model-capability issue.
2. **`minimax-m3` and `z-ai/glm-5.1` tie at 90%** on N=10 — strong
   candidates for headline runs. `minimax-m3` is ~3× cheaper than
   `glm-5.1` per spec.
3. **The N=10 calibration is consistently optimistic** vs. E8.8's
   N=178 headline (e.g. deepseek-v4-pro: 80% → 70% → 23%). The cost
   per spec, however, is roughly stable because token usage is a
   function of agent budget (12 turns) more than spec difficulty.
4. **`deepseek/deepseek-v4-pro` is the most expensive cell** at $0.0093.
   It hits 70% accuracy here, but the high token consumption (18k input
   tokens/spec, 50% above the pool average) means it scales worst
   to a large corpus. Worth keeping in the panel for DeepSeek-family
   diversity, not as the workhorse.
5. **`openai/gpt-oss-120b` is shockingly cheap** at $0.00069/spec — a
   full E8.8 redo on it alone would cost $0.12. Useful as the
   high-throughput "openai-oss family" representative.

### Recommended panel for next runs

The 5-model OR pool is healthy enough to use as-is. If we want to trim
cost for E8.7 v2, dropping `deepseek/deepseek-v4-pro` would cut the
budget by ~30% while retaining a 4-family panel (anthropic-isn't-here
notwithstanding):

| Tier | Model | Role |
|---|---|---|
| Cheap workhorse | `minimax/minimax-m3` | 90% acc at $0.003/spec |
| Tool specialist | `moonshotai/kimi-k2.6` | 60% acc, moonshot family |
| Tool specialist | `z-ai/glm-5.1` | 90% acc, z-ai family |
| Diversity | `openai/gpt-oss-120b` | 50% acc, openai-oss family |
| (Optional) | `deepseek/deepseek-v4-pro` | 70% acc, deepseek family — drop if budget-tight |

## Conclusion (classification: **positive**)

Successfully recalibrated. The 5-model OR pool yields **\$96 ceiling** for
the full Phase D headline run (1100 specs × pass^3), comfortably under
the $300+ figure from E8.0a's original frontier-heavy panel. The 0% twins
from E8.8 were a free-endpoint artifact, not real capability gaps.
