# RQ3 trace-property failure model (e4.5)
- status: done
- result: positive — `dynamism_live` is the dominant pass/fail driver across all three candidate models, with `trace_depth` and `cross_server` as the next two largest effects

## Question / hypothesis

RQ3 is the project's "why does it fail" model. Given the same set of
forward-distilled tasks and the same candidate models, which **trace
properties** carry most of the explanatory weight for the trace-align
pass/fail outcome?

**H1 (headline)**: at least one trace-feature has a clearly non-zero
coefficient (|β| > 0.5) AND a clearly non-zero drop-column importance
(loglik-loss > 0.5) in the pooled fit, AND the top-importance feature
agrees across at least 2 of the 3 candidate models. (We are looking for a
*consistent* failure driver, not noise across models.)

**H2 (sanity)**: the IRLS fit converges within 50 iterations on all three
per-model fits and the pooled fit, with the ridge λ at its default 1e-3.

## Method (realized)

Substrate: the existing **v3** evaluation artifacts — 56 forward-distilled
TaskSpecs in replay mode evaluated by `anthropic/claude-haiku-3.5`,
`anthropic/claude-haiku-4.5`, and `qwen/qwen3-8b`. 168 (model, spec)
cells. All artifacts already on disk (git-ignored). No new LLM calls.

Features (fixed order, from `ComplexityProfile` + spec dynamism):

| index | feature | scale |
|---|---|---|
| 0 | `trace_depth` | int (successful agent tool calls) |
| 1 | `runtime_branching` | {0, 1} |
| 2 | `state_coupling` | {0, 1} |
| 3 | `cross_server` | {0, 1} |
| 4 | `dynamism_live` | {0, 1} |
| 5 | `dynamism_stateful` | {0, 1} |

(`dynamism = static` is the reference level, encoded as both dummies =
zero. `state_coupling` and `dynamism_stateful` are perfectly collinear in
this substrate — every stateful_write spec has state_coupling = True —
which the ridge handles cleanly without NaN.)

Fit: pure-Python IRLS (Newton-Raphson) with L2 ridge (λ = 1e-3) on the
non-intercept coefficients. Importance is the **drop-column log-likelihood
loss**: refit without each feature and measure how much the data
log-likelihood drops. No new dependency (numpy is transitively present in
the project, but `failure_model.py` is dep-free so the report can be
regenerated in a minimal env).

Reproduce:

```bash
uv run dmcp rq3-failure-model \
  --evals "anthropic/claude-haiku-3.5:evals/v3_haiku35.jsonl" \
  --evals "anthropic/claude-haiku-4.5:evals/v3_haiku45.jsonl" \
  --evals "qwen/qwen3-8b:evals/v3_qwen3.jsonl" \
  --specs specs/v3.jsonl \
  --title "RQ3 e4.5 trace-property failure model (v3, 56 specs × 3 models)" \
  --output /tmp/e4.5_report.md \
  --json-out docs/experiments/e4.5_numbers.json
```

Distilled numbers committed as `docs/experiments/e4.5_numbers.json`. The
markdown output is regenerable from the same JSON — this experiment doc is
the canonical write-up.

## Decision rule (pre-registered, fixed before running)

**Primary**: importance ranking under the **pooled** fit.

- **positive** iff (a) **at least one feature has |coefficient| > 0.5 in
  the pooled fit**, (b) that feature's drop-loglik loss > 0.5, AND
  (c) the same feature is the top driver in at least 2 of the 3 per-model
  fits. (Robust, model-consistent failure driver.)
- **neutral** iff (a) holds but the top driver disagrees across models, OR
  the top driver in each model is different from the pooled top driver.
- **negative** iff no feature satisfies (a) and (b). (The trace properties
  collected do not explain pass/fail at all — back to the drawing board on
  the feature set.)

Convergence and ridge: all four fits (3 per-model + pooled) must converge
in ≤ 50 IRLS iterations at λ = 1e-3 for the result to count.

## Data

All four fits converged (≤ 9 iterations).

### Per-model — top feature by drop-loglik loss

| model | top feature | β | odds ratio | drop-loglik loss |
|---|---|---|---|---|
| `haiku-3.5` | `trace_depth` | −0.534 | 0.586 | +1.284 |
| `haiku-4.5` | `dynamism_live` | −6.249 | 0.002 | +2.450 |
| `qwen3-8b` | `dynamism_live` | −7.060 | 0.001 | +3.935 |

For `haiku-3.5`, `dynamism_live` (β = −2.079, drop +1.109) is the
**second-largest** importance — only narrowly behind `trace_depth`.

### Pooled fit (168 cells, intercept = +2.330)

| feature | coefficient | odds ratio | drop-loglik loss |
|---|---|---|---|
| `dynamism_live` | **−3.110** | **0.045** | **+6.606** |
| `trace_depth` | −0.097 | 0.908 | +1.682 |
| `cross_server` | −0.757 | 0.469 | +0.871 |
| `runtime_branching` | −0.328 | 0.720 | +0.261 |
| `state_coupling` | −0.897 | 0.408 | +0.000 |
| `dynamism_stateful` | −0.897 | 0.408 | +0.000 |

`state_coupling` and `dynamism_stateful` carry identical coefficients
because they are perfectly collinear in v3 (every stateful_write spec has
state_coupling = True). The ridge splits their contribution evenly; their
joint drop-loglik loss is positive but vanishes when only one is removed.

## Result

**POSITIVE** on the pre-registered primary.

- `dynamism_live` has β = **−3.110** (|β| > 0.5 ✓) and drop-loglik loss
  **+6.606** (> 0.5 ✓) in the pooled fit — together carrying ≈ 70 % of
  the pooled importance budget (6.606 / 9.420).
- It is the top driver in `haiku-4.5` and `qwen3-8b` (2 / 3 models — the
  decision-rule threshold), and the second driver in `haiku-3.5` by only
  a small margin behind `trace_depth`.

The model-consistent failure driver is **task dynamism**: live, changing
data substantially raises the failure rate relative to static tasks, even
under replay scoring. `trace_depth` and `cross_server` carry the next
two largest pooled effects.

## Conclusion & implication

- The headline RQ3 finding **agrees with the conceptual axis from
  `docs/CONCEPT.md`**: dynamism is the difficulty knob, not just a
  taxonomy label. The dynamism dummies dominate the pooled fit (β ≈ −3,
  odds ratio ≈ 0.045 for `dynamism_live` vs the `static` reference)
  across all three candidate models. This is the empirical defense of
  the project's choice to stratify by dynamism class.
- **`trace_depth`** is consistently a secondary negative driver — deeper
  traces are harder regardless of model. This validates the
  `ComplexityProfile.trace_depth` field as a stratification axis for
  the leaderboard (E4.7) and the degradation curves (E2.7).
- **`cross_server`** is reliably negative in the pooled fit
  (β = −0.757, odds ratio ≈ 0.47) and in haiku-3.5 / haiku-4.5, but
  near-zero for qwen3 — suggesting model-specific tolerance for
  cross-server routing.
- **`runtime_branching`** carries a small pooled effect; it may need a
  larger or more varied substrate to separate cleanly. Listed as a
  stratification axis but not a load-bearing failure driver at this
  scale.
- **`state_coupling` / `dynamism_stateful`** collinearity is an artifact
  of v3's substrate (every stateful_write spec couples state by
  construction). E3's expansion to a more varied substrate may eventually
  decorrelate them; for now the report flags this honestly (their joint
  pooled β = −1.79, but neither's individual drop-loglik is significant
  because of the perfect substitution).
- **CLAUDE.md hard invariants** are untouched: the failure model is a
  diagnostic, not part of scoring. A regression test (in
  `tests/test_failure_model.py`) reads `evaluator.py` / `judge.py` source
  and fails if either ever imports the failure-model module.
- E4.5 is `done`. The empirical pattern matters for paper §5 ("difficulty
  axes"): we can now show that dynamism is not just a label but
  *the* dominant statistical driver. Tighter coefficients live in E4.7's
  ≥5-model leaderboard run on the full E3 substrate, reusing the same
  `dmcp rq3-failure-model` CLI without code changes.
