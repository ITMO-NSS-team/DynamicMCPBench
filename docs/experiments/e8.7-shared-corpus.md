# E8.7 — Shared corpus (first headline run, Phase C scope)

## Question / hypothesis

Can the cross-family generation panel from E8.6 (explorer-family ≠
distiller-family, 3 explorer shards, 4th-family validator) author a
meaningful headline corpus on the free model pool from E8.0b at zero
direct cost, in a single overnight run?

Concretely: target **~150-200 keepers** at "Phase C" scope
(`--per-strategy 8 × 3 complexities × 15 strategies` over the 16-server
`manifests/local.json` substrate). The full ~1100-spec scope (Phase D)
stays the next-phase target after this proof-of-feasibility.

## Method

- **Manifest:** `manifests/local.json` (16 servers: time, fetch, git,
  sqlite, fs, memory, wikipedia, arxiv, …). The full 147-server
  `servers.json` is the eventual target but requires more endurance
  testing for stability — saved for a follow-up phase.
- **Explorers (cross-family panel, all on the free endpoint):**
  `deepseek-v4-pro` (deepseek), `glm-5p1` (z-ai), `kimi-k2p6` (moonshot).
- **Distiller candidates** (ordered; cross-family picker per shard):
  `glm-5p1, deepseek-v4-pro, minimax-m2p7, kimi-k2p6`. The picker yielded:
  - shard 0: deepseek explorer → glm-5p1 distiller
  - shard 1: glm explorer → deepseek-v4-pro distiller
  - shard 2: kimi explorer → glm-5p1 distiller
- **Validator (4th family, advisory):** `minimax-m2p7` (minimax).
- **Concurrency:** 3-lane parallel (one key per shard,
  `FREE_MODELS_API_KEY[, _2, _3]`).
- **Resume:** `--resume` always on. Multiple kill/relaunch cycles across
  bug fixes (see "Bug chain" below); all preserved via
  `provenance.goal_id`.

## Pre-registered decision rule

A run is **positive** if it produces ≥ 150 keeper specs, ≥ 10 generation
strategies represented, both intra- and cross-server scopes covered, and
at least three depth bins populated.

## Reproduce

```
uv run python scripts/build_corpus.py \
  --manifest manifests/local.json \
  --explorer-models deepseek-v4-pro,glm-5p1,kimi-k2p6 \
  --distiller-candidates glm-5p1,deepseek-v4-pro,minimax-m2p7,kimi-k2p6 \
  --validator-model minimax-m2p7 \
  --complexities simple,medium,hard \
  --per-strategy 8 \
  --budget 12 \
  --concurrency 3 \
  --out data/corpus_e8.7 \
  --resume
```

## Results

### Headline

**178 keeper specs distilled from 310 traces (57% distill rate), 94 of
which (53%) pass the 4th-family validator.** Wall time: **9h 41m**
across 5 kill/relaunch cycles (each cycle preserved via `--resume`;
total in-cycle wall-clock was the same as one clean run thanks to
per-goal idempotence). Direct cost: **$0** (free endpoint).

### Operational signals

- **Free-endpoint p95 latency:** unchanged from E8.0b calibration
  (~120 sec/call). The explorer's `llm_error` rate stays ~50–67% per
  goal, but partial traces still distill cleanly thanks to PR #63's
  `max_tokens=16k` bump.
- **Transport errors caught:** 32+ during run 5 alone (`APIConnectionError`
  / `ReadError` from the free endpoint). All caught by PR #66's broader
  except — no shard crashes after that fix landed.

## Conclusion (classification: **positive**)

**178 > 150** keeper specs; 14 of 15 strategies represented; both intra-
and cross-server scopes covered; depth bins populated 100 / 52 / 26.
Pre-registered decision rule met on every axis.

The cross-family contract held end-to-end: every spec carries
`provenance.{explorer_model, explorer_family, distiller_model,
distiller_family, validator}` and the families differ per-row by
construction. The 4th-family validator marked 94 of 178 as `valid` —
advisory, not authoritative; downstream filters can drop the invalid
ones if needed.

### Bug chain ironed out (PRs 62 – 66)

The first headline launch surfaced a chain of four real bugs in fast
succession; the corpus this report describes is the run that survived
all of them. Logged for future runs:

| PR | Symptom | Fix |
|---|---|---|
| #62 | 0 goals — `RuntimeError: Attempted to exit cancel scope` | `_fetch_tool_specs` uses `anyio.fail_after` instead of `asyncio.wait_for` (anyio scope compatible with MCP task groups) |
| #63 | 0 specs from 2 of 3 shards — kimi distiller dumps CoT to content | `DISTILLER_MAX_TOKENS = 16384` (was 4096 default); reasoning models now have CoT + structured-output headroom |
| #64 | Phase 2 no-op on resume | `--resume` bypasses the coarse `specs.jsonl exists` reuse check |
| #65 | `UnboundLocalError: json` mid-Phase-2 | Removed the function-local `import json` shadow in Phase 1's else branch |
| #66 | All 3 shards crashed on `APIConnectionError` during distill | Broad `except Exception` mirrors the explorer wrapper; transient transport errors no longer kill a subprocess |
