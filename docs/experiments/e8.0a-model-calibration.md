# E8.0a — Model pool calibration

## Question / hypothesis

Which subset of a 10-model field minimizes the cost of the headline runs
(E8.7 / E8.8) without giving up accuracy at the top of the leaderboard? The
EXPERIMENTS_SUITE §1.1 panel was frontier-heavy; the user redacted it
2026-06-04 toward small/mid + cheap-large models. The calibration measures
actual `$/spec` against live OpenRouter prices and extrapolates to the
target corpora, replacing list-price guesses with measurements.

## Method

- **Pool (user-locked, 10 models, glm 4.7 → 5.1):** sonnet-4.6, minimax-m3,
  qwen3.7-max, glm-5.1, kimi-k2.6, qwen3-coder-plus, haiku-4.5,
  gemini-3.1-flash, deepseek-v3.1, llama-3.3-70b-instruct.
- **Sample:** N=10 specs (the first 10 of `specs/v3.jsonl`, mixed
  domains — time, fetch, git, sqlite).
- **Condition:** `dmcp eval --replay --pool target --pool-size 8
  --p-alt 0.5 --budget 12`. Replay (not live), so server flakiness can't
  pollute the cost signal.
- **Pricing:** live `https://openrouter.ai/api/v1/models` fetched at run
  time (343 models cached), with `dmcp/pricing.py` as the pinned fallback.
- **Extrapolation:** `mean_cost_usd × corpus_size × pass_k` for
  `corpus_size ∈ {600 (E8.8), 1100 (E8.7)}` × `pass_k ∈ {1, 3, 5}`. The
  accuracy from N=10 specs is held constant — a deliberate
  approximation, OK for *picking* a pool, not for publishing.

## Pre-registered decision rule

The recommended pool is the **Pareto frontier on accuracy vs. \$/spec**
(each step up in accuracy must beat every cheaper model), with two human-
overrides: (a) drop models that returned **zero usage** (the script reports
those at \$0 cost and the frontier picker mis-classifies them as
"cheap-best"); (b) keep at least one frontier-tier anchor so the leaderboard
has a ceiling reference even if it's not on the auto-frontier.

## Reproduce

```
uv run python scripts/cost_calibration.py \
  --n 10 \
  --specs specs/v3.jsonl \
  --reference-traces traces/v3.jsonl \
  --manifest manifests/servers.json \
  --out reports/cost_calibration \
  --json docs/experiments/e8.0a_numbers.json
```

### Pareto frontier (auto + human-curated)

The auto-picker returned `[gemini-3.1-flash, llama-3.3-70b, minimax-m3]` —
the leading entry is the broken-model artifact (zero cost, zero accuracy
reads as the cheapest-and-no-worse-than-zero). After the override rules:

**Auto-frontier (clean): `[llama-3.3-70b, minimax-m3]`** — but llama-3.3-70b
at 30% is too weak for the headline.

## Conclusion (classification: **positive**)

**The calibration succeeded at its purpose.** We have measured `$/spec`
under realistic conditions and an honest extrapolation that says the full
E8.7 (1100 × k3) run will land at **~$310 on the full 10-model pool, ~$170
if we drop the most expensive model**. The cheap-skew bet pays off:
**minimax-m3 matches qwen3.7-max and glm-5.1 on accuracy at one-third the
cost**, and beats sonnet-4.6 on accuracy at one-tenth the cost on this
sample (90% vs 80%).

### Recommended final pool (7 models)

The shortlist drops the 2 broken models + the too-weak llama, keeps the
diversity that lets RQ1/RQ3/RQ4 stratify by family + tier:

| # | Model | Why kept | E8.7 \$ (1100×k3) |
|---|---|---|---|
| 1 | `minimax/minimax-m3` | $/correct champion | $12.68 |
| 2 | `qwen/qwen3-coder-plus` | Tool specialist; cross-family with Qwen3.7 | $19.31 |
| 3 | `z-ai/glm-5.1` | Tool specialist; tied accuracy floor | $26.92 |
| 4 | `moonshotai/kimi-k2.6` | Agentic specialist; different family | $29.42 |
| 5 | `anthropic/claude-haiku-4.5` | Small-fast Anthropic; cross-family pairs | $35.76 |
| 6 | `qwen/qwen3.7-max` | Large open; matches frontier-tier accuracy | $41.43 |
| 7 | `anthropic/claude-sonnet-4.6` | Frontier anchor (ceiling reference) | $143.23 |

**Total E8.7 (1100 × k3) on this 7-model panel: $308.75.**
Without sonnet-4.6 it's **$165.52** — the user can choose whether
the ceiling-reference is worth $143.

### Findings & followups (non-blocking)

- **Frontier-picker has a broken-model artifact** — a model that returned
  zero usage shows as $0 and lands on the Pareto frontier. Fix: in
  `_pareto_frontier`, exclude rows with `runs > 0 and prompt_tokens == 0`
  (the live-fetch case where the API call silently produced nothing).
  Logged as a small followup; doesn't affect this report's
  recommendation (manual override.)
- **`google/gemini-3.1-flash` and `deepseek/deepseek-v3.1` IDs need
  verification.** The live-fetch returned 343 models including these
  prefixes, so the IDs were probably valid as listings — but our agent
  loop got empty content / no tool calls back, which on OpenRouter
  usually means the model didn't honor the tool-call schema or returned a
  refusal. A `--simulate-misses` or a model-snapshot rotation might
  recover them; for E8.7 they're dropped.
- **sonnet-4.6 at 80% acc on this sample is below the large-cheap models**
  (90%). That's almost certainly v3-sample noise rather than a real
  inversion — but it's a flag that **the full corpus may not need
  sonnet-4.6 to anchor the ceiling**. Decision deferred to the user.
