# RQ1 headline: answer-match vs trace-align (e4.4)
- status: done
- result: positive — Kendall's τ between rankings is **−0.816** (rankings nearly reversed); overall false-pass rate of answer-match is **63 %**, false-fail just **1.8 %**

## Question / hypothesis

RQ1 is the project's headline claim about scoring: a final-answer string
match against a reference answer (the shape prior work uses) is unstable
under live, stateful agent traces. The DynamicMCPBench scorer instead
checks trace/effect alignment — every checkpoint is a claim about an
*action the agent took on the world*, not a substring in its reply. RQ1
quantifies how much these two scoring shapes disagree on the same agents.

**H1 (headline)**: the two scorers do not agree on which model is best.
Concretely, **Kendall's τ between the two model rankings is below 1.0**
— ideally well below. If τ ≈ 1.0, both methods rank models identically
and final-answer scoring is fine; if τ is small or negative, the answer-
match scorer would lead a leaderboard astray.

**H2**: the false-pass rate (trace-align ✗, answer-match ✓) dominates the
false-fail rate (trace-align ✓, answer-match ✗). Mechanism: live LLMs
parrot the right keywords from their context even when they didn't
actually call the tools the spec demands, so substring/Jaccard overlap is
generous about awarding pass to candidates that, in fact, didn't do the
work.

## Method (realized)

Substrate: the existing **v3** evaluation artifacts — 56 forward-distilled
TaskSpecs from the public-API expansion (see
`memory/project_v3_scale_tier2.md`), evaluated in `--replay` mode by three
candidate models (`anthropic/claude-haiku-3.5`, `anthropic/claude-haiku-4.5`,
`qwen/qwen3-8b`). All artifacts already on disk (git-ignored) — no new LLM
calls were needed.

For each (model, task_id) cell:

- **trace-align verdict** = `EvaluationResult.passed` from
  `evals/v3_{haiku35,haiku45,qwen3}.jsonl`.
- **answer-match verdict** = `score_answer(cand_final, ref_final, threshold=0.5)`
  from `dmcp/baselines/answer_match.py`, where:
  - `cand_final` comes from the candidate trace's
    `seed_metadata.exploration.final_message` (in
    `evals/v3_*_traces.jsonl`),
  - `ref_final` comes from the reference trace's same field (in
    `traces/v3.jsonl`), joined via `task_id → source_trace_id` from
    `specs/v3.jsonl`.

Aggregation in `dmcp/baselines/rq1_compare.py` (see CLI below):

- Per-model trace-acc, answer-acc, agreement, false-fail, false-pass rates.
- **Kendall's τ** (τ-b, custom implementation — no scipy dep) between the
  vectors `[trace_acc per model]` and `[answer_acc per model]`.
- Optional over-time stability — Kendall's τ between two re-runs' binary
  trace-pass vectors over the same `task_id` set.

Reproduce:

```bash
uv run dmcp rq1-compare \
  --evals "anthropic/claude-haiku-3.5:evals/v3_haiku35.jsonl" \
  --evals "anthropic/claude-haiku-4.5:evals/v3_haiku45.jsonl" \
  --evals "qwen/qwen3-8b:evals/v3_qwen3.jsonl" \
  --candidate-traces "anthropic/claude-haiku-3.5:evals/v3_haiku35_traces.jsonl" \
  --candidate-traces "anthropic/claude-haiku-4.5:evals/v3_haiku45_traces.jsonl" \
  --candidate-traces "qwen/qwen3-8b:evals/v3_qwen3_traces.jsonl" \
  --specs specs/v3.jsonl \
  --reference-traces traces/v3.jsonl \
  --threshold 0.5 \
  --title "RQ1 e4.4 v3-substrate comparison (56 specs × 3 models)" \
  --output docs/experiments/e4.4_report.md \
  --json-out docs/experiments/e4.4_numbers.json
```

Raw eval/trace JSONLs stay git-ignored per the experiments rule. Distilled
numbers are committed as `docs/experiments/e4.4_numbers.json`; the
markdown rendering output (`e4.4_report.md`) is regenerable and not
committed — this experiment doc is the canonical write-up.

## Decision rule (pre-registered, fixed before running)

**Primary**: Kendall's τ between the per-model rankings.

- **positive** iff `τ < 0.5` AND `overall_false_pass_rate >
  overall_false_fail_rate` AND the per-model ordering under the two
  methods is different in at least one pair. (A τ below 0.5 means the
  rankings noticeably diverge; the false-pass-dominates-false-fail
  condition is the mechanism the hypothesis predicts.)
- **neutral** iff `τ ∈ [0.5, 1.0)` AND the rankings agree on the top
  model — the methods broadly agree but disagree on tail ordering.
- **negative** iff `τ ≥ 1.0` (identical rankings — final-answer scoring is
  fine) OR `overall_false_fail_rate > overall_false_pass_rate` (the
  hypothesized mechanism is inverted).

Threshold `0.5` is the pre-registered default; threshold sensitivity is
an interesting follow-up but does not gate the primary decision.

## Data

Per-model accuracy (threshold = 0.50):

| model | n | trace-align acc | answer-match acc | agree | false-fail | false-pass |
|---|---|---|---|---|---|---|
| `anthropic/claude-haiku-4.5` | 56 | 45 % | 89 % | 48 % | 4 % | 48 % |
| `qwen/qwen3-8b` | 56 | 23 % | 89 % | 30 % | 2 % | 68 % |
| `anthropic/claude-haiku-3.5` | 56 | 21 % | 95 % | 27 % | 0 % | 73 % |

Headline (168 (model, spec) cells in total):

- **Kendall's τ between rankings** = **−0.816**
- **overall false-fail rate** (trace-align ✓, answer-match ✗) = **1.8 %**
- **overall false-pass rate** (trace-align ✗, answer-match ✓) = **63.1 %**
- **overall agreement rate** = **35.1 %**

Trace-align ranking: `haiku-4.5 (45 %) > qwen3-8b (23 %) > haiku-3.5
(21 %)`. Answer-match ranking: `haiku-3.5 (95 %) > haiku-4.5 (89 %) =
qwen3-8b (89 %)`. The strongest model under trace-align (haiku-4.5)
becomes the worst under answer-match; the weakest under trace-align
(haiku-3.5) becomes the best under answer-match.

Over-time stability: the only available rerun (`evals/replay_haiku45_run2.jsonl`,
8 specs) shares **0 task_ids** with the v3 substrate, so the harness's
over-time column is wired but not populated by this PR. A scheduled rerun
of the same v3 spec set would close that gap; deferred to E1.5 / E4.7.

## Result

**POSITIVE** on the pre-registered primary.

- `τ = −0.816 ≪ 0.5` (decision-rule margin met by a wide margin — the
  rankings are not merely "noisy", they are almost completely *reversed*).
- `false_pass (63 %) ≫ false_fail (1.8 %)` (mechanism prediction held —
  generous-string-match credits candidates that didn't do the work).
- The per-model ordering under the two methods disagrees on every pair.

## Conclusion & implication

- The headline RQ1 claim is supported with margin: **using
  final-answer string match would invert the leaderboard** at the haiku-4.5
  / haiku-3.5 / qwen3 substrate scale, attributing the best score to the
  model that least often does the right thing.
- The 63 % false-pass rate concretely illustrates the failure mode the
  project's headline pivot was designed to fix: a candidate that parrots
  enough of the prompt's keywords gets credit even when it never invoked
  the required tools. Trace-align's 0–4 % false-fail rates further show
  that when an agent *does* the work, its phrasing variation is not
  punishing it under either scorer — the disagreement is one-way.
- The hard CLAUDE.md invariant ("never grade the final answer") is now
  not just a stylistic preference: it has a quantitative defense. The
  experiment also confirms the orthogonality contract — the answer-match
  module is comparison-only, never imported by `evaluator.py` or
  `judge.py` (an automated test enforces this; see
  `tests/test_rq1_compare.py::test_answer_match_module_is_not_imported_by_evaluator_or_judge`).
- The remaining over-time-stability column (per-model trace-align τ
  between re-runs) needs a rerun of the same v3 spec set — wired in the
  harness, but blocked here on a substrate-matched second run. E1.5's
  refresh path and E4.7's leaderboard re-runs are the natural places to
  fill it in.
- E4.4 is `done`. The headline argument now has a reproducible 56 × 3
  cell foundation; scaling to the ≥5-model leaderboard (E4.7) and the
  full substrate (E3) will tighten the numbers without changing the
  structural finding.
