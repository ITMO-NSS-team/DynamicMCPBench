# RQ4 scorer-vs-human + 200-task validation (e4.6)
- status: planned
- result: — (awaiting human annotation pass)

## Question / hypothesis

RQ4 asks whether the DynamicMCPBench scorer agrees with humans about
which candidate trajectories pass and which fail. The agreement target
matters because the rest of the project's claims (RQ1 / RQ2 / RQ3) all
treat the **trace-align verdict** as ground truth — if humans broadly
disagree with it, every downstream claim is up for revision.

**H1 (primary)**: on the 200-task validation subset, **Cohen's κ
between Tier-1 (deterministic) verdicts and the human consensus
verdict is ≥ 0.70**. Tier-2 (LLM judge) κ is ≥ 0.70.

**H2 (multi-rater check)**: **Krippendorff's α** over the full grid
(human raters + Tier-1 + Tier-2 treated symmetrically as raters)
**≥ 0.70**.

**H3 (replay determinism)**: between two independent Tier-1 runs over
the same `(task_id, candidate_model)` cells, **< 5 %** of cells have a
flipped verdict.

## Method (locked here; data collection deferred to the annotation pass)

This PR ships the **harness + annotation protocol + reproduce command**
and pre-registers the decision rule. The empirical numbers (κ / α /
flip-rate) will be added once human annotators complete the pass; only
then does E4.6 move from `planned` to `done`. Per `docs/AUTONOMY.md`,
the autonomous loop never invents human numbers, and an empirical-claim
step is not `done` until its report carries a result.

Substrate: the existing v3 forward-distilled spec set
(`specs/v3.jsonl`, 56 specs) plus its v3 evals
(`evals/v3_{haiku35,haiku45,qwen3}.jsonl`) and candidate traces
(`evals/v3_{model}_traces.jsonl`). When E3 lands at substrate scale,
the subset target moves from 56 to 200 specs with the same procedure;
the harness already targets 200 by default.

### 1. Generate the validation subset

```bash
uv run dmcp rq4-subset specs/v3.jsonl \
  --n 200 --seed 0 \
  --subset-out evals/rq4_subset.jsonl
```

Selection is deterministic stratified sampling over the
`(dynamism, complexity_bin)` grid (see `dmcp/baselines/rq4_subset.py`).
Quotas are proportional with a floor of 1 per non-empty stratum so the
corners of the grid (e.g. `static|5+`) aren't dropped at small N. Empty
strata are noted in the manifest.

### 2. Emit the annotation template

```bash
uv run dmcp rq4-subset specs/v3.jsonl \
  --n 200 --seed 0 \
  --subset-out evals/rq4_subset.jsonl \
  --candidate-traces evals/v3_haiku35_traces.jsonl \
  --candidate-traces evals/v3_haiku45_traces.jsonl \
  --candidate-traces evals/v3_qwen3_traces.jsonl \
  --rater alice --rater bob --rater carol \
  --annotation-out evals/rq4_annotations.template.jsonl
```

One row per `(task_id, candidate_trace_id, rater_id)` with empty
`verdict` / `justification` / `minutes_spent` fields for the rater to
fill in.

### 3. Annotation protocol (rater-facing)

- **Verdict**: read the spec's `prompt`, the candidate's tool calls (in
  the candidate trace), and the candidate's final assistant message.
  Mark **pass** iff the candidate successfully accomplished what the
  prompt asked for *as evidenced by the actual tool calls and their
  results*. **Do not** decide based on whether the final-message text
  alone is plausible — RQ1 has already shown that's misleading.
- **Justification**: 1–3 sentences explaining the verdict. If the
  candidate did the work but the wording was off, mark **pass** and
  note the wording mismatch. If the candidate produced a plausible
  reply without doing the work, mark **fail**.
- **Minutes spent**: rough self-report (used to budget the pass).
- **Three raters per cell** are the minimum; ties (1 pass / 1 fail) are
  inconclusive and dropped from κ / α — the report counts them
  separately.
- **Calibration**: 10 warm-up cells (not in the 200) where raters
  discuss disagreements before going independent.

### 4. Aggregate and score

```bash
# Pick the same Tier-1 evals (judge off) you'd score against.
# Optional: a second Tier-1 run for the replay flip-rate.
uv run dmcp rq4-agreement \
  --annotations evals/rq4_annotations.filled.jsonl \
  --tier1-evals evals/v3_haiku45.jsonl \
  --tier2-evals evals/judge_haiku45.jsonl \
  --replay-run-b evals/v3_haiku45_run2.jsonl \
  --consensus-out evals/rq4_consensus.jsonl \
  --subset-size 200 \
  --title "RQ4 e4.6 agreement (200 specs × 3 raters)" \
  --output docs/experiments/e4.6_report.md \
  --json-out docs/experiments/e4.6_numbers.json
```

The harness computes per-tier Cohen's κ, the full-grid Krippendorff's α
(raters + Tier-1 + Tier-2 as raters), the per-tier false-pass /
false-fail rates against the human consensus, and the Tier-1 verdict
flip rate between the two runs.

### 5. Report (template — to be filled in after annotation)

The completed report carries:

- subset size, n_annotated_cells, n_consensus_cells, n_tie_cells;
- Tier-1 / Tier-2 κ ± bootstrap CI (the harness emits the point
  estimate; bootstrap CIs will be added in a tiny follow-up);
- α and the rater × scorer agreement table;
- replay flip rate;
- per-stratum agreement breakdown (live_read vs stateful_write etc.).

## Decision rule (pre-registered, fixed before data collection)

**Primary**: Tier-1 Cohen's κ on the 200-task subset.

- **positive** iff `tier1_kappa ≥ 0.70` AND `tier2_kappa ≥ 0.70`
  AND the **replay flip rate is < 5 %**.
- **neutral** iff `0.50 ≤ tier1_kappa < 0.70`. (Substantial but
  short of the headline target — calls for a follow-up that tightens
  Tier-2 thresholds and revisits calibration.)
- **negative** iff `tier1_kappa < 0.50` OR replay flip rate ≥ 5 %.
  (The scorer is materially out of step with humans, or replay isn't
  deterministic enough — both of which break downstream claims and
  block the paper headline until fixed.)

**Krippendorff's α** is the secondary check (must also clear 0.70).
False-pass / false-fail rates are reported per tier and per dynamism
stratum but do not gate the verdict.
