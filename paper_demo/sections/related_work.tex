\section{Related Systems}
\label{sec:related}

DMCP Studio is, to our knowledge, the first interactive demonstration system
built specifically around \emph{answer-agnostic, effect-based} grading of
MCP agents over live servers. We situate it against three families of prior
work; Table~\ref{tab:comparison} summarizes the contrast.

\input{tables/comparison}

\paragraph{MCP agent benchmarks.} A large and fast-growing line evaluates
agents directly on MCP servers, pushing breadth and realism
\citep{fan2025mcptoolbench++, mo2025livemcpbench, lei2025mcpverse,
wang2025mcp} with execution-grounded scoring \citep{servers25mcp,
gao2025mcp} or planted-distractor partial credit \citep{bandi2026mcp}, and
others stress-test or diagnose failure \citep{wu2025mcpmark, yin2025livemcp,
guo2026mcp}. These ship as \emph{batch harnesses and fixed datasets}: a
practitioner runs a script and reads a score. None exposes the construction
and scoring of a task as an inspectable, interactive surface, and each
ultimately grades a final answer, an outcome, or a tool selection rather
than path-agnostic effects.

\paragraph{Reproducible tool-execution environments.} Because live tools
drift, a separate line makes execution reproducible---caching call responses
behind a virtual server \citep{guo2024stabletoolbench, guo2025stabletoolbench},
retrieving similar cached responses on a miss \citep{cheng2025travelbench},
or scoring milestones, forbidden actions, and dual-control state
\citep{lu2025toolsandbox, barres2025tau}. \citet{yao2024tau} compares final
database state rather than the path. DMCP Studio adopts this deterministic-replay
stance for its REPLAY mode, but turns it outward: replay is not only a
stability mechanism, it is the thing the visitor watches and toggles.

\paragraph{Agent-evaluation tooling and generators.} Toolkits such as
\citet{liu2025mcpeval} generate and verify MCP tasks, and others build tool
graphs and back-instruct questions \citep{shen2024taskbench,
guo2026unitoolbench, shi2025taskcraft}. These are developer libraries run
from a terminal. DMCP Studio differs in \emph{modality} (an interactive,
visual studio rather than a CLI) and in \emph{thesis} (it dramatizes the
gap between effect-scoring and answer-matching, a contrast a batch tool
never surfaces).

In short, prior systems are batch harnesses, replay back-ends, or generator
libraries; DMCP Studio is an interactive front-end that makes
trace-grounded, effect-based evaluation \emph{visible}---and, through its
LIVE/REPLAY switch, both reproducible and demonstrably live. It is the
companion demonstration to the DynamicMCPBench methodology
\citep{dynamicmcpbench2026}; this paper describes the system and its
evaluation, not the methodology, with which we keep overlap minimal.
