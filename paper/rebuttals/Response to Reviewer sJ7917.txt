DISTILLER FIDELITY

A call in a successful trajectory does not establish that it was not spurious. Trace grounding buys provenance and achievability; the abstraction's correctness depends on the distiller and validator, and we were wrong to call it a guarantee. We are removing the "by construction" wording for a narrower, measured invariant: every required checkpoint is grounded in a successful call in its trace.

We audited 100 TaskSpecs by hand from the released corpus: 264 retained tool_effect checkpoints, 200 of the non-retained calls, 67 listed alternatives.

| audited | result | Wilson 95% CI |
|---|---|---|
| grounded in a successful call | 261/264 = 98.9% | 96.7-99.6 |
| of those, necessary to the goal | 261/261 = 100% | 98.5-100 |
| non-retained calls redundant | 188/188 resolved = 100% | 98.0-100 |
| specs missing a required effect | 1/100 = 1% | 0.2-5.4 |
| listed alternatives equivalent | 67/67 = 100% | 94.6-100 |
| valid as written (4 minor, 1 permissive) | 95/100 | |

Twelve further were unresolved, mostly recovery after a failure; counting all twelve as errors gives 94%.

The missing effect was never executed in its reference trace, so it is a reference-validation miss, not the distiller dropping what it saw. We will release the item-level labels and rubric so it can be recomputed.

Two limits, and we can bound the first rather than name it. The equivalence figure is precision, not recall; measuring recall needs an exhaustive oracle over 1,168 tools. But under replay the binding constraint is the recorded cache, not the listed set: a tool the reference never called is blocked whether or not we listed it, measured at 7 to 9 percent of tasks. Distiller output is also filtered: a fourth-family validator and trace check discard a quarter of parseable output.

At corpus scale the same holds: 5.63 recorded calls become 2.52 required checkpoints, chains of five or more 13.5 to 4.1, and 15.5% of checkpoints admit more than one tool.

The concession costs an unconditional guarantee. What remains is the framework's point: ground truth that is externally observable effects rather than a reference string or tool list, scored along any path producing them, achievability established by a real execution.

One clarification about scoring: every reported number comes from deterministic checks. The optional LLM judge was not enabled for any result, so the leaderboard and chain-length findings carry no model judgment; the human study you cite validates that scorer. That covers scoring, not construction: the distiller and validator are LLMs, which is why we measured their output.

TOOL UNIVERSE AND RETRIEVAL

Agreed, and we have now run it. On 150 tasks balanced across chain depth we replaced the curated pool with retrieval over the full 1,168-tool catalog, exposing only the top eight tools by similarity, against released verdicts for the same model and tasks.

| chain depth | retrieval, full catalog | curated | delta |
|---|---|---|---|
| short (1-2) | 64.0% | 62.0% | +2.0 |
| medium (3-4) | 30.0% | 74.0% | -44.0 |
| long (5+) | 16.0% | 36.0% | -20.0 |
| all 150 | 36.7% | 57.3% | -20.7 |

The curated column is one model, one attempt, 50 tasks per bucket, so its short-medium ordering is within noise; the paper's curve is pass^3 over 24 models.

The cost is entirely compositional: single-step tasks are unaffected and the retrieval curve stays monotone. Of the 274 unmet checkpoints, 64% are tools the agent never called. So the setting is materially harder, as you expected, but adds no difficulty axis and did not manufacture the chain-length result: it sharpens it.

DISTILLER SELECTION

The distiller is not chosen with reference to the agent evaluated: candidates run only after the corpus is frozen, so no candidate can shape its own tasks.

Each explorer shard gets the first model in an ordered distiller pool whose family differs from the explorer's, keeping the two cross-family. Distillation runs at temperature 0 through a structured tool-call schema with a token budget large enough that reasoning models do not truncate; unparseable output yields no spec, and parsed specs pass the validator and trace check. The pool spanned several frontier families, GLM-5.1 and DeepSeek-V4-Pro among them. We did not run a controlled cross-distiller study, and will state that as a limitation with the audit.
